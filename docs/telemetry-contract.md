# Telemetry contract v1

The executable contract is `backend/app/schemas/__init__.py`; the exported `telemetry.schema.json` is generated from it. Live OpenAPI is available at `/openapi.json` and `/docs`.

```json
{"schema_version":1,"device_id":"demo-GPS-001","sequence_number":1042,"recorded_at":"2026-10-27T01:10:00Z","location":{"fix_valid":true,"latitude":1.30001,"longitude":103.80001,"speed_kmh":35.6,"heading_deg":125,"satellites":12,"hdop":0.9},"status":{"network_type":"wifi","battery_percent":null,"external_power":true,"firmware_version":"0.1.0"}}
```

- Authenticate using `Authorization: Bearer <device token>`. JSON device identity must match.
- Sequence is a nonnegative signed-64-bit integer unique across device restarts. Firmware must persist it; the simulator persists its counter and queue.
- `recorded_at` must include timezone information; supported capture dates start at 2020 and may be at most five minutes ahead of server time. Arrival time is generated by the server.
- Latitude [-90,90], longitude [-180,180], heading [0,360), speed [0,400] km/h. Non-finite numbers and unknown fields are rejected.
- A no-fix event uses `location: {"fix_valid": false}` with coordinates absent or null. It records heartbeat evidence without inventing a valid location.
- Status fields have documented defaults in JSON Schema. Optional measurements remain absent/null; no estimates are fabricated.
- Batch body: `{"samples": [...]}` with 1–200 records, all belonging to the authenticated device. Request body limit: 256 KiB.
- Acknowledgment: `{"accepted": [1042], "duplicates": []}`. Retire only acknowledged IDs.
- Exact normalized duplicates are acknowledged. Changed data at an existing sequence returns 409 and rolls back the entire batch. Correct the counter/payload before retrying.
- Invalid records reject the entire request. Devices should retain and diagnose failures rather than blindly discarding samples.
